## Decision 1 — interface detection is `edge_splits`-only; delete the derived cell level and `depth()`

**Decision: option (a).** `edge_splits` plus active-cell edge incidence is the
single source of truth for interface detection. There is no per-cell level, no
level derived from `parent_cells`, and no `depth()` helper. `parent_cells`
keeps its P0-P2 meaning — the index of the source cell in the mesh that
produced this level — and is documented as opaque, level-scoped provenance for
the frozen `parent_cell(child) -> Result<CellId>` accessor. Option (b) (remap
`parent_cells` to the active-cell space with self-parents) is **rejected**.

### Rationale

- The runtime probe in the review is reproducible from the code: in
  `new(unit_square(1), [CellId(0)])`, the child at active index 0 stores
  `parent_cells[0] = CellId(0)` and reports depth 0, while the carried root at
  active index 4 stores `parent_cells[4] = CellId(1)` and walks `4 → 1 → 0 → 0`
  to report depth 2. Depths are wrong and inconsistent inside one mesh, so
  "interface by cell level" was never delivered.
- The load-bearing rule is already `edge_splits.contains_key(edge)`
  (`src/nonconforming_refinement.rs:375-377`) followed by the incidence `retain`
  at `:381`. The `depth()` branches at `:369-371` and the carried-root loop at
  `:361-366` only add edges that the split-key rule already adds (and any
  non-split edge they add is dropped by `:381`).
- `depth()` (`:18-30`) indexes `parent_cells[i]` without bounds checking and
  loops without a cycle guard. `coarsen` even remaps parent ids "to keep `depth`
  in bounds" (`:645-670`) — a workaround for a value no consumer needs.
  Removing the helper removes both hazards; no new guard is required.
- The P0-P2 test asserts `parent_cell(child) == CellId(parent_i)` for every
  parent and every child (`tests/nonconforming_refinement.rs:96`) and uses the
  parent id for physical-tag lookup (`:225`). Changing `parent_cells` semantics
  would break ADR-0001 frozen parity. Keeping it costs nothing: it has no other
  consumer.

### Exact implementation instructions (engineer)

1. **Delete** `fn depth(...)` at `src/nonconforming_refinement.rs:18-30`.
2. In `refine`, replace the root construction at `:358-381` (both the carried
   `self.mesh.hanging` loop and the depth comparison) with one rule: a root is
   any canonical edge key from the edge→active-cell incidence map for which
   `edge_splits.contains_key(&edge)` holds. Use a `BTreeSet` to keep emission
   deterministic. Keep `collect_subedges` (`:32-69`) and its visited set.
3. Factor that rule into a private helper (for example
   `discover_hanging(edge_splits, incidence) -> Result<Vec<HangingNode>>`) and
   call it from both `refine` and `coarsen` (see Decision 2, step 8). Do **not**
   change the P0-P2 `new` path (`:147-262`), whose hanging nodes come from the
   marking and match the same rule.
4. Keep `parent_cells.push(CellId(i))` in `new` (`:192,197`) and `refine`
   (`:337,342`) verbatim.
5. In `coarsen`, replace the representative-cell assignment at `:645-670` with:
   for each sibling group `p` in `self.children`, every cell produced from that
   group gets `parent_cells[new_index] = CellId(p)` (the parent-level group
   index). Remove the comment about keeping `depth` in bounds. No frozen test
   asserts coarsened parent values and no accessor indexes with them.
6. Update rustdoc: the `parent_cells` field comment (`:92-96`) and the `refine`
   doc block (`:274-282`) must not claim that levels are derived from
   `parent_cells` or that roots are self-parents.

## Decision 2 — per-transition `introduced_midpoints` selects coarsening removals

**Decision:** add a **private field on the transition** (never on
`NonconformingMesh`, never in `edge_splits`):

```rust
// on NonconformingRefinement (transition-only, level-scoped)
introduced_midpoints: BTreeMap<CellId, BTreeSet<VertexId>>,
```

Semantics: for sibling group `p` (a `CellId` indexing that transition's parent
mesh / `children`), the set holds the `VertexId`s of midpoints **newly created**
while refining `p` — precisely the midpoints of `p`'s three canonical edge keys
that were absent from `edge_splits` at the start of that transition. A midpoint
**reused** from an earlier level via `edge_splits` is excluded even if both its
masters are vertices of the sibling group. A midpoint created for an edge
shared by two marked groups belongs to **both** groups' sets. No level is
stored anywhere.

### Rationale

- The current heuristic at `src/nonconforming_refinement.rs:544-555` treats any
  group vertex whose `midpoint_parents` masters are also group vertices as
  newly introduced. In the repro (`unit_square(1)` → `new(...,[0])` →
  `refine(&[4])`), the level-1 interface midpoint (id 4, masters 1 and 3) is
  reused for the diagonal of cell 1; both masters are group vertices, so it is
  misclassified, added to `removed`, and condition 3 at `:597-606` rejects a
  legal derefinement. The 3-element `local.len()` check at `:552` is therefore
  wrong for any group with fewer freshly created edges and must be deleted.
- A per-group map (rather than one flat `BTreeSet<VertexId>`) is required
  because `coarsen(marked)` accepts multiple sibling groups in one call
  (RFC §8); a flat set would remove midpoints belonging to groups that are not
  being coarsened.
- A single "owning group" map is also insufficient: a midpoint on an edge
  shared by two simultaneously marked groups must be attributable to both, or
  coarsening the other group first would leave a dangling reference.
- ADR-0003 §4 compatibility: keys are level-scoped parent `CellId`s of the
  same kind already stored in `children`; values are mesh-local `VertexId`s.
  Both are renumbered/compacted on `coarsen` and invalidated with all other
  IDs. No persistent or path-based IDs are introduced. The field lives on the
  transition in `NonconformingRefinementHistory`, consistent with the
  active-only mesh model (`NonconformingMesh` gains no inactive-cell data).
- Interaction with RFC §8: the candidate set is exactly
  `introduced_midpoints[p]`; the existing geometric orphan cascade
  (`:577-594`) still removes nested sub-edge midpoints that become unused, and
  the existing `edge_splits` drop/cascade (`:675-681`) still applies. A reused
  midpoint is never in a later transition's candidate set, so it persists
  under the §8 persistence clause until the introducing transition is undone
  or it becomes geometrically orphaned. Recomputing hanging nodes from
  `edge_splits` after coarsening restores an interface that was inactive at
  the deeper level.

### Exact implementation instructions (engineer)

1. Add the private field to `NonconformingRefinement` (`:136-143`). All four
   construction sites must populate it: `new`, `refine`, `coarsen`,
   `root_transition`.
2. `new`: snapshot the (empty) split map before midpoint creation (`:167-178`),
   then for every marked parent `i` insert the midpoint of each canonical edge
   key of `parent.cells()[i]` into `introduced_midpoints[CellId(i)]`. Shared
   edges appear in both groups.
3. `refine`: `let prior = self.mesh.edge_splits.clone();` before the creation
   loop at `:309-323`. After the loop, for each marked parent `i`, for each of
   its three canonical edge keys `k`, if `!prior.contains_key(&k)`, insert
   `edge_splits[&k]` into `introduced_midpoints[CellId(i)]`. Reused keys are
   skipped. (MSRV 1.70: no let-chains.)
4. `coarsen`: replace `:544-555` with
   `removed.extend(self.introduced_midpoints.get(&CellId(p)).cloned().unwrap_or_default());`
   per restored group `p`. Delete the `local.len() != 3` error. Optionally
   sanity-check that each candidate is a key of `midpoint_parents` and a vertex
   of a child of `p`; a missing group entry is an empty set, not an error.
5. Keep conditions 1–4 (`:497-555`, `:596-616`), the orphan cascade
   (`:577-594`), the vertex remap (`:618-643`), the `edge_splits` cascade and
   `midpoint_parents` remap (`:675-688`), and boundary collapsing
   (`:699-761`) as they are — conditions 3/4 now evaluate the corrected
   removal set.
6. In the returned transition, carry `introduced_midpoints` forward: for each
   `(p, mids)` in `self.introduced_midpoints`, keep the entries whose midpoint
   is not in `removed`, remapped with `renumber(m)?`. Restore groups no longer
   have four children, so their entries can be dropped without loss.
7. `root_transition` (`:957-982`): initialise the field to an empty map. The
   history removes levels by popping, so `coarsen` is not called on this view.
8. Replace the input-hanging carry/filter at `:607-616` with two steps:
   (a) check condition 4 against `self.mesh.hanging` (reject if a slave or
   master is in `removed`); (b) recompute the result's `hanging` with the
   Decision 1 discovery helper from the coarsened active cells and the
   surviving `edge_splits`.
9. **Test consequence (engineer owns this; architect did not touch tests):**
   `tests/nonconforming_multilevel.rs:255-266`
   (`coarsen_rejects_surviving_vertex_reference`) encodes the defect — it
   asserts `Err` for exactly the repro whose correct result is the original
   level-1 mesh. Replace it with
   `coarsen_reused_interface_midpoint_restores_parent`: assert `Ok`, and that
   `vertices()`, `cells()`, `edge_splits` and `hanging_nodes()` equal the
   first-level mesh (levels 1 and 2 in that test), plus a successful
   `hanging_constraints().close()`. Keep
   `coarsen_rejects_neighbor_dependency` (`:238-249`) as an `Err` case: the
   shared newly-created midpoint is in both groups' sets, so surviving cells
   still reference a removed midpoint. Do **not** modify the frozen
   `tests/nonconforming_refinement.rs`. The active plan's `must_haves`
   (`.carter/state/plans/active/001-multi-level-nonconforming/README.md:19`)
   still lists the old test name; maestro/PM should rename it.

## Decision 3 (non-blocking) — validate untrusted `NonconformingMesh` inputs

**Decision:** keep `NonconformingRefinementHistory::new(mesh: NonconformingMesh)
-> Self` unchanged (mirrors `RefinementHistory`), keep `NonconformingMesh`
fields public (the new tests read them, e.g.
`tests/nonconforming_multilevel.rs:88,137,157`), and add validation additively:

1. `NonconformingMesh::validate(&self) -> Result<()>`: check
   `original_vertices <= vertices.len()`; equal `parent_cells`/`cells` lengths;
   every `VertexId` in `cells`, `edge_splits` keys/values, `midpoint_parents`
   keys/values, `hanging`, `boundary_edges` and `boundary_vertices` is in
   range; distinct edge endpoints; each `midpoint_parents` entry agrees with
   `edge_splits[edge_key(m0,m1)]`. Structural checks only — geometric validity
   remains a caller obligation, as in `History::new`'s current docs.
2. `NonconformingRefinementHistory::try_new(mesh) -> Result<Self>` (additive,
   preferred for untrusted input) calls `validate`. `new` calls
   `debug_assert!(mesh.validate().is_ok(), "invalid NonconformingMesh")` and
   stores the mesh as before.
3. `NonconformingRefinementHistory::refine` (`:1040-1050`) calls
   `self.mesh().validate()?` **before** `root_transition`/transition refine, so
   a base mesh containing e.g. `VertexId(usize::MAX)` returns `Err` instead of
   panicking. Optionally `debug_assert!` the invariant in
   `NonconformingRefinement::refine`/`coarsen` (their meshes are internal).
4. Add the invariants to the `NonconformingMesh` rustdoc (`:80-114`). No new
   dependencies, no signature removals.

## Compatibility verification

- **ADR-0001 (P0-P2 frozen):** `NonconformingRefinement::new`, the
  `parent_cell`/children/boundary accessors and all frozen tests are untouched;
  only the multi-level `refine`/`coarsen` paths change.
- **ADR-0003 §3 (additive):** one private transition field, one mesh `validate`
  method, one history `try_new` constructor; no removed or renamed public API.
- **ADR-0003 §4 (index-based IDs, invalidation):** both new records use
  level-scoped index IDs, are remapped on coarsening, and never encode cell
  paths or persistent identity.
- **Active-only model:** `introduced_midpoints` is transition-scoped; no
  inactive cells or cross-level cell identity enter `NonconformingMesh`.
- **ADR-0002:** no upstream code, constants or fixtures are reused; this is an
  original design decision.
